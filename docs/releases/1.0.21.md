# Supreme Legacy 1.0.21 — unpublished candidate

**Not a published release.** This candidate prepares a distinct artifact version for source changes already merged to maintained Supreme main after the immutable [v1.0.20](https://github.com/wickidcow/SF_Supreme/releases/tag/v1.0.20). The previous release JAR must remain byte-for-byte unchanged.

## Changes already present on main

- Restore historic Supreme Soulbound equipment interoperability, including the proper native metadata and canonical legacy lore, without replacing saved item IDs, issuing duplicate death returns or changing equipment recipes.
- Improve armor potion/enchantment compatibility and preserve levels, amplifiers, visibility, configurations, and historic item identities with focused regression coverage.
- Apply reviewed build-library modernization and expose real compiler deprecation/unchecked diagnostics; clean up verified unchecked collection creation without modifying gameplay behavior.
- Existing machine state, storage field names, power costs, processing speed, production rates, item amounts and recovery policies remain unchanged by **this version-only candidate**.

## Merge / publication requirements

Current source changes are *not* proven safe for every historic stored world merely by compilation. Before any reviewed merge or distinct new `v1.0.21` release, require:
1. Exact-head Java 21 raw-JAR verification, all Maven/JUnit tests, no packaged test/core classes, and unchanged canonical plugin identity.
2. Actual Paper 1.21.11, 26.2 and **stable** Paper 26.3 compatibility source checks, and appropriate native integration/restart receipts on the source-pinned candidate core. 26.1.2 is an advisory compile-only target; do not claim its world migration.
3. Native behavior and historic-data acceptance for Soulbound equipment, armor enchantment/effect configuration and applicable machine storage/recovery/rollback. No arbitrary-world, Folia region-ownership or performance certification is inferred from an API compile.
4. An immutable publisher gate: reject any existing tag/release; no `gh release upload --clobber`, archive overwrite, server deployment or automatic legacy workflow reactivation. The existing `v1.0.20` asset stays intact.
5. Re-pin the reviewed **merged-main commit** into the full 44-addon Slimefun Legacy bundle and re-run all current exact-head API, native stack, reproducibility and package checks before a new core release.

The current PR updates only release identity/build policy/docs and does **not** publish or deploy anything.
